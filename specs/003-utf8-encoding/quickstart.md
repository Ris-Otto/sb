# Quickstart: Validating UTF-8 Encoding

This feature closes a real, observed defect and makes UTF-8 handling explicit across command-line
I/O, file reads/writes, and file-existence detection. It changes no CLI surface, storage format,
or leaflet-builder behavior from `001-song-leaflet-generation` — only encoding correctness.

## Prerequisites

- .NET 10 SDK installed.
- Repository cloned, working directory at the repo root.
- Windows (the originally observed defect and this feature's target platform — see plan.md).

## Run the automated test suite

```powershell
dotnet test sb.sln
```

Expected outcome: all tests pass, including:
- `PathTextTests` — `PathText.NormalizeForFileSystem` is a no-op for an already-NFC path, and
  normalizes an NFD-form path to match.
- `SongCommandsTests` — a `--text` value naming an existing file whose path contains a non-ASCII
  character (å/ä/ö) is read as that file's contents, not treated as literal text (the exact
  regression this feature closes).
- Extended `DocumentStoreTests`/`ChapterStoreTests`/`SongStoreTests`/`DocumentTemplateTests` —
  round-tripping real fixture content containing å/ä/ö through write-then-read produces identical
  text.

## Manually verify the original defect is fixed

```powershell
dotnet run --project sb -- documents create utf8check "UTF-8 Check" -p C:\Temp\utf8check
dotnet run --project sb -- chapters add utf8check -n main
dotnet run --project sb -- songs add utf8check main "Hon var så liten" `
  sb/Tests/TestFiles/hon_var_så_liten.txt 1
dotnet run --project sb -- documents build utf8check -f multi-column
```

**Expected outcome**:
- `songs add` succeeds and the song's stored text matches the real fixture's lyrics (not the
  literal path string) — confirm via `sb/Tests/TestFiles/hon_var_så_liten.txt`'s content appearing
  in `C:\Temp\utf8check\Chapters\main\hon_var_s_liten.yml` (or equivalent slugged filename).
- The built `utf8check.tex` contains the song's actual Swedish lyrics, correctly accented, not a
  garbled file path.

## Manually verify console output displays correctly

```powershell
dotnet run --project sb -- documents list
```

**Expected outcome**: any non-ASCII title/name already stored (e.g. from the command above)
displays with correct å/ä/ö characters in the terminal, not replacement characters or mojibake.
